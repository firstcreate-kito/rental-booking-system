# 管理画面（バックエンド）UIコーディングルール

- 対象: `public/admin.html`（＝スタッフが毎日使う業務ツール）
- 位置づけ: **お客様向けフロント（tokens.css）とは別系統**。フロントは「不安を与えない・世界観を揃える」ためのデザイン、バックエンドは「速く・正確に・間違えずに操作できる」ための実務デザイン。
- 作成: 2026-08-20 ／ 状態: **案（レビュー用）**

---

## 0. 5つの狙い（要点）

このルールは、次の6つを実現するために作る。

1. **PC・スマホの両方で使いやすい**
2. **タブレットはPCと同じレイアウト**にする
3. **画面から要素が隠れない**（はみ出し・見切れを作らない）
4. **ボタンの押し間違えを防ぐ**
5. **操作はテキストリンクではなくボタン**にする
6. **入力枠は程よい大きさ**にする

以下は、それを具体的な条文にしたもの。

---

## 1. レイアウトと画面幅（要点1・2）

### A1-1 折り返し幅は「スマホだけ」を分ける（必須）
- **`max-width: 720px` 以下＝スマホ用レイアウト**、それより広ければPC用レイアウト。
- これにより**タブレット（768px〜）は自動的にPC表示**になる（要点2）。
- 中間のブレークポイントを増やさない（PC/スマホの2段だけ）。

```css
/* 既定（スマホ）を先に書き、PCで上書きする */
.tabs{ /* スマホ: 横スクロールできる帯 */ }
@media (min-width: 721px){
  .tabs{ /* PC: 折り返して全部見せる */ }
}
```

### A1-2 スマホを基準に書き、PCで上書きする（必須）
- CSSは**スマホの見た目を先に**書き、`@media (min-width: 721px)` でPCを足す。
- 「PCで作ってスマホで縮める」書き方をしない（隠れ・はみ出しの原因）。

### A1-3 本文（`body`）を横スクロールさせない（必須）
- ページ全体が横に動く状態を作らない。**幅の広いもの（表・カレンダー）は、その要素の中だけで横スクロール**させる（→ A3-1）。

---

## 2. 画面から隠れさせない（要点3）

### A2-1 幅の広い表は「スマホ＝縦組みカード／PC・タブレット＝表」（必須）
- 列の多い表は、**スマホ（640px以下）では「1件＝1カード」の縦組み**に切り替える（項目名＋値の2列）。横スクロールは項目名が見えなくなり読みにくいため、原則こちらを採用する。
- **タブレット・PC（641px以上）は従来どおりの表**。それでも収まらない場合のみ、スクロール用の箱で包む。
- 実装は `<table class="resp">` を付けるだけ。各セルへの項目名（`data-label`）は、描画後に**見出し行から自動付与**する共通処理（`initRespTables`／`labelRespCells`）が行う。各描画関数を個別に書き換えない。

```html
<table class="resp"><thead>…</thead><tbody id="xxBody"></tbody></table>
```
```css
@media (max-width: 640px){
  table.resp thead{ display:none; }
  table.resp tr{ display:block; border:1px solid var(--line); border-radius:10px; margin-bottom:12px; }
  table.resp td{ display:flex; justify-content:space-between; } /* 左=項目名 右=値 */
  table.resp td::before{ content:attr(data-label); color:var(--muted); font-weight:600; }
  table.resp td.act{ /* 操作ボタンは横幅を確保して押しやすく */ }
}
```

### A2-2 タブの帯は見切れさせない（必須）
- タブが多い（予約一覧／見学／代理予約／…）。スマホでは**横スクロールできる帯**にし、はみ出したタブに指で届くようにする。PCでは折り返して全部見せる。

### A2-3 モーダル（ポップアップ）は画面内に収める（必須）
- 高さは `max-height: 90vh` とし、**中身が長いときはモーダルの中だけスクロール**。
- **閉じるボタンは常に見える位置**（上部固定）に置く。背景クリックでも閉じられるようにする。
- 幅は `min(560px, 92vw)` のように、スマホでも左右に余白が残る形にする。

### A2-4 固定バー・ヘッダーは中身を隠さない（必須）
- 上部固定のヘッダーやバーを置く場合、その高さぶん本文に余白（`padding-top`）を確保し、**最初の行が隠れない**ようにする。

---

## 3. 押し間違えを防ぐ（要点4）

### A3-1 押せるものの高さは 44px を下回らない（必須）
- ボタン・入力・セレクト・タブは **最小 44px**。
- **`.btn.sm`（小ボタン）でも 36px 以上**。26pxのような極小は作らない。

### A3-2 ボタン同士は 8px 以上あける（必須）
- 隣り合うボタンの間隔（`gap`）は **8px 以上**。行の折り返しでも詰まらないようにする。
- 一覧の行内に操作ボタンを並べるときも同様。

### A3-3 取り消せない操作・危険な操作は分けて置く（必須）
- **削除・キャンセル・お断り**など後戻りしにくい操作は、
  - 色を**赤（`--bad`）**にして他と区別する、
  - **安全なボタンから離して**置く（真隣に「保存」と「削除」を並べない）、
  - **確認ダイアログ**（`confirm`）を必ず挟む。

### A3-4 送信ボタンは連打させない（必須）
- 送信中はボタンを `disabled` にし、表示を「処理中…」に変える。二重登録・二重キャンセルを防ぐ。

---

## 4. 操作はボタンで（要点5）

### A4-1 「行動」はボタン、「移動・参照」だけリンク（必須）
- 保存・確定・削除・作成・切替などの**操作は必ず `<button class="btn">`**。
- `<a>` は、別ページや外部への**移動**や、メール・電話などの参照のみ。
- **テキストの中に操作を紛れ込ませない**（押せる範囲が狭く、押し間違える）。
  ※現状の管理画面はこの原則を満たしている。今後も維持する。

### A4-2 ボタンの種類は用途で決める（推奨）
| 種類 | クラス | 使いどころ |
|---|---|---|
| 主 | `.btn` | その画面の主操作（塗り） |
| 副 | `.btn.ghost` | 補助操作（白地＋枠） |
| 危険 | `.btn.danger` | 削除・キャンセル等（赤） |
| 小 | `.btn.sm` | 一覧の行内など（ただし36px以上） |

---

## 5. 入力枠（要点6）

### A5-1 入力枠は程よい大きさにする（必須）
- **高さ 40〜44px、`font-size: 16px`、`padding: 10px 12px`** を基準にする。
- `font-size` を 16px 未満にしない（**スマホで入力時に画面が勝手に拡大するのを防ぐ**）。

```css
input, select, textarea{
  width: 100%;
  min-height: 44px;
  font-size: 16px;
  padding: 10px 12px;
  border: 1px solid var(--line);
  border-radius: 8px;
}
```

### A5-2 ラベルは枠の上に置く（必須）
- プレースホルダーだけで済ませない。**項目名は入力枠の上にラベルとして常に表示**する（入力後も何の欄か分かる）。

### A5-3 入力欄は縦に積む（推奨）
- スマホでは1列（縦積み）を基本にする。PCでは2〜3列に並べてよいが、**1つの入力が極端に狭くならない**ようにする（最小 220px 程度）。

---

## 6. 状態の見せ方（実務の見やすさ）

### A6-1 状態は色だけに頼らない（必須）
- 予約状態（本予約／商談中／キャンセル）・入金状況などは、**色＋文字（ラベル）**で示す。色覚特性のある方や、白黒印刷でも判別できるようにする。

### A6-2 未処理の件数はバッジで出す（推奨）
- 見学・変更リクエストのように「対応待ち」があるものは、タブに**件数バッジ**を出し、タブを開かなくても気づけるようにする（現状踏襲）。

### A6-3 長い一覧は見出し行を固定する（推奨）
- 行数が多い表は、スクロールしても**列見出し（thead）が上に残る**ようにする（`position: sticky`）。どの列か見失わない。

---

## 7. 色・文字（バックエンド独自）

### A7-1 管理画面は独自パレットを使う（必須）
- フロントの `tokens.css` は**読み込まない**。管理画面は業務ツール用の独自色（現状：インディゴ `--brand:#4338ca` ほか）を使う。
- 色は `:root` の変数から選び、本文に直書きしない。

### A7-2 文字は小さくしすぎない（推奨）
- 本文 14px 以上、補足 12px 以上。**12px 未満を業務情報に使わない**。

---

## 8. レビュー前チェックリスト

- [ ] スマホ幅（〜720px）で**横スクロールが起きていない**（表は枠内スクロール）
- [ ] タブレット幅（768〜1024px）で**PCレイアウト**になっている
- [ ] タブ・ボタン・モーダルが**画面から見切れていない**
- [ ] ボタン・入力・タブが**44px以上**（小ボタンでも36px以上）
- [ ] 隣り合うボタンの間隔が**8px以上**
- [ ] **削除・キャンセルが赤＋確認ダイアログ**、安全な操作と離れている
- [ ] 操作は**ボタン**（テキストリンクで操作させていない）
- [ ] 入力枠は**16px・高さ44px前後**、ラベルは枠の上
- [ ] 状態は**色＋文字**の両方で示している
- [ ] 送信ボタンは**連打防止**（送信中は無効化）

---

## 9. 現状とのギャップ（適用時の作業メモ）

このルールを `public/admin.html` に適用する場合、主に次を直す：

1. **レスポンシブ未対応** → スマホ用の `@media`、表の枠内スクロール、タブの横スクロール帯を追加。
2. **入力枠が小さい**（font14px/約34px）→ 16px・44px基準へ。
3. **小ボタンが小さい**（`.btn.sm` 約26px）→ 36px以上へ。
4. ボタン間隔・危険操作の分離を各所で担保。

※ルール策定が目的の第一段階。実際の適用（`admin.html` の改修）は別ステップで行う。
