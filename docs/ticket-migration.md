# 既存チケットの移行（#82）

公開前に販売済みだった既存チケット（回数券）を、新システムの会員へ引き継ぐ仕組みと手順。

## 方針（確定事項）
- **1回 = 1時間**で換算（システムは時間管理）。
- **メール一致で自動付与**：お客様が**資料と同じメールアドレス**で会員登録／ログインし、
  マイページ（または予約時のチケット選択）にアクセスした時点で、自動で本物のチケットが付与される。
- **有効期限 = 公開日から1年**。
- 出典データ：提供Excelの **Sheet2（最新）**。合計 **41名 / 252時間**（AB共通34名177h・東別院7名75h）。
- 補正済み：日下部圭子さん メール `gmai.com→gmail.com` ／ 細田紗希さん 東別院 残26時間。

## スペース対応
| 資料の種別 | 付与対象スペース |
|---|---|
| AB共通 | 名駅防音室A（meieki-piano-a）＋B（meieki-piano-b） |
| 東別院 | 東別院24hグランドピアノ練習室（higashibetsuin-piano-24h） |

## 仕組み（実装）
- テーブル `pending_tickets`（付与待ち）に移行データを保持。
- `src/lib/ticket-migration.ts` の `claimPendingTicketsForCustomer()` が、
  マイページのチケット表示（`GET /api/mypage/tickets`）と予約時のチケット取得
  （`GET /api/mypage/usable-tickets`）の入口で、メール一致の未付与チケットを本物の
  `tickets` へ発行し、`pending_tickets` を claimed 済みにする（**何度呼んでも二重付与しない**）。
- 管理画面 → **システム状態タブ** 下部「付与待ちチケット」で付与状況（付与済み/未付与）を確認可能。

## 本番への適用手順

### 1) テーブル作成（先に済ませてOK・空でも無害）
```
npm run db:migrate:remote   # migrations/0037_pending_tickets.sql を本番D1へ
```

### 2) コードのデプロイ
GitHub Actions → Deploy → production（通常どおり）。

### 3) 【公開直前】移行データの投入
1. `seeds/pending_tickets.sql` の有効期限を確定（公開日＋1年）に置換：
   ```
   sed -i 's/__VALID_UNTIL__/2027-09-01/g' seeds/pending_tickets.sql   # 日付は公開日+1年に
   ```
2. 本番D1へ投入：
   ```
   wrangler d1 execute albe_booking --remote --file=./seeds/pending_tickets.sql
   ```
   ※ `INSERT OR IGNORE`＋id固定のため、誤って2回流しても重複しません。

### 4) お客様への事前案内メール（文面テンプレ）
> 件名：【レンタルスペースALBE】新予約システムへの移行と、お手持ちチケットの引き継ぎについて
>
> いつもレンタルスペースALBEをご利用いただきありがとうございます。
> このたび予約システムを新しくいたしました。お手持ちの回数券（チケット）は、新システムでも引き続きご利用いただけます。
>
> ■ チケットの引き継ぎ方法
> 新システムで、**これまでご連絡いただいていたメールアドレスと同じアドレス**で会員登録（またはログイン）してください。
> マイページを開くと、残りのチケットが自動で表示されます。
>
> ・会員登録／ログイン： https://booking.space-albe.com/mypage.html
> ・チケットの有効期限：公開日から1年間
>
> ※別のメールアドレスで登録されると自動反映されません。その場合はお手数ですが店舗までご連絡ください。
