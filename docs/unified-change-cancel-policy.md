# 変更・キャンセル 統一ポリシー（確定版）

- 対象：レンタルスペースALBE 予約システム
- 確定日：2026-09-06（オーナー合意）
- 位置づけ：これを**統一見解の正**とする。既存の `change-cancel-policy-spec.md`（#76 Phase1）・`policy-per-space-handover.md`（#99/#100）はこの文書で上書き・統合する。

## 0. 大原則（承認制・完全自動にしない）

- お客様は**マイページから「変更リクエスト」「キャンセルリクエスト」を送る**。
- リクエスト時に**料金（キャンセル料・返金額・差額）を画面表示**し、**理解・同意のうえ送信**。
- 管理者はメール受信後、管理画面で内容を確認し、**「承認」または「返金額を任意に調整して承認」**して確定する。
- **必ず管理者が一度チェックしてから確定**する（顧客操作だけでは確定しない＝完全自動にしない）。
- 承認で予約は**自動的に書き換え**（変更）／**キャンセル確定＋返金記録**（キャンセル）まで行う。
- 金額の実徴収・実返金（振込・カード返金操作）は従来どおり人が実行。システムは金額確定・記録・通知まで。

## 1. キャンセルポリシー（現金予約・料率）

判定は**当初のご利用日**基準。返金額＝支払済み − キャンセル料（未入金は返金0）。手数料は差し引かない。

### 標準スペース（名駅フリー ほか）
| 時期 | キャンセル料 |
|---|---|
| 31日前まで | 無料 |
| 30〜15日前 | 50% |
| 14日前〜前日 | 80% |
| 当日 | 100% |

### 名駅防音室A・B／東別院24h
| 時期 | キャンセル料 |
|---|---|
| 8日以上前 | 無料 |
| 2〜7日前 | 50% |
| 前日・当日 | 100% |

※本番 `cancel_policies` は上記と一致済み（変更不要）。

---

## 2. 変更ポリシー（現金予約・日時変更＝ずらす）

「ずらすだけ（同額）」は原則無料。ただし**直前はキャンセル扱い**。判定は当初利用日基準。

### 標準スペース
| 時期 | 日時変更の扱い |
|---|---|
| 前日より前 | 無償 |
| 当日 | キャンセル扱い＝100% |

### 名駅防音室A・B／東別院24h
| 時期 | 日時変更の扱い |
|---|---|
| 前々日より前 | 無償 |
| 当日・前日 | キャンセル扱い＝100% |

- **減額（時間短縮・日数削減）**：減少分を「一部キャンセル」とみなし、上記キャンセル料率を減少分に適用（当初利用日基準）。
- **増額（時間追加・日数追加）**：空き次第で受付（差額は現地/個別精算 or 追加請求）。
- 変更後にキャンセルした場合のキャンセル料は**当初のご利用日**を基準に計算（遠い日へ移してからの無料キャンセルを防ぐ）。

## 3. チケット予約：キャンセル

- 現金キャンセル料は常に **¥0**（ペナルティはチケット時間の失効のみ）。
- **前々日まで**：消費したチケット時間を**全額返還**（再予約に使える）。
- **当日・前日**：チケット時間は**失効（返還なし）**。

---

## 4. チケット予約：変更（日時変更）

| 時期 | 変更の扱い |
|---|---|
| 前々日より前 | チケット時間を**全額返還**（＝実質自由に変更。新しい予約で改めて消費） |
| 当日・前日：時間枠の増減なし（同じ時間数で日時をずらす） | **無償・チケット返還なし**（消費を新予約へ付け替え） |
| 当日・前日：時間枠の**減少**あり | 減少分は**キャンセルとみなし失効（返還なし）**。残りは付け替え |
| 当日・前日：時間枠の**増加** | チケットでの追加消費は**不可**。増やしたい分は**新規予約**で対応いただく |

## 5. オンライン導線（確定フロー 2026-09-06）

**大方針：枠は"申込時に即確保（仮押さえ）"。正式確定とお金（返金・差額）は管理者の「承認」で行う。**
理由：減額・増額があっても**基本は顧客のご要望に応える**ので枠はすぐ押さえる。ただし金額は必ず管理者が一度チェックして確定する（完全自動にしない）。

### ステップ
1. **お客様（マイページ）が申込**：変更/キャンセルの画面で**料金（返金・差額）を自動表示 → 同意 → 送信**。
2. **送信した瞬間（即時）**：
   - 変更：**新しい枠を「変更申請中（tentative/仮押さえ）」としてカレンダーに確保**（他のお客様に取られない）。旧枠は承認時まで保持し、承認で解放。
   - キャンセル：**「キャンセル申請中」として枠を確保解除の保留**にする（第三者予約を防ぎつつ、確定は承認時）。
   - 申込内容と**「お客様に表示した金額（返金/差額）」**を"精算待ち"として記録し、管理者へ通知メール。
3. **管理者（管理画面）が承認**：精算待ち一覧に**金額入力枠**が表示され、**お客様に提示した金額がプリセット**されている。
   - 管理者は**金額を任意に変更**でき、**「承認」ボタン**を押すと**正式に変更後の予約が確定**する：
     - 変更：予約を新枠で確定（旧枠のカレンダーを解放・新枠を確定）、**返金（減額時）／追加請求（増額時 #88）を確定金額で実行**、確定メール送信。
     - キャンセル：キャンセルを確定（枠解放）、**返金を確定金額で実行**、確定メール送信。

### 確定した実装方針（2026-09-06）
- **変更申込時の旧枠**：申込時に**即・新枠へ移動**（旧枠を解放・新枠を確保、状態＝変更申請中）。承認では金額のみ確定。
- **増額（時間追加）の差額**：承認時に**追加請求リンク（既存 #88）**で回収。

### 承認ボタン後のアクション（支払い方法で分岐・既存機能を流用）
確定金額（管理者が入力）に対して、元の支払い方法に応じて実行する：

**減額（返金）**
- カード / PayPal … Stripe / PayPal で**自動返金**（既存 #87）。
- 銀行振込 / コンビニ … 顧客へ**返金額の明示＋返金先口座を返信してもらうメール**（既存 `refundAccountRequestEmail`）。

**増額（追加請求）**
- カード / PayPal … 追加請求を実行。**追加料金の明示＋決済リンクを発行**して決済を促す（既存 #88 `additionalChargeEmail`）。
- 銀行振込 / コンビニ … 顧客へ**増額金額の明示＋追加分の振込（決済）リンクを載せたメール**。

**返金なし・追加請求なし（金額の増減なし）**
- 該当例：無償の日時変更（同じ時間数の移動）／返金0のキャンセル（当日100% など・未入金予約）／チケット予約（現金精算なし）。
- カード・銀行振込・コンビニ**いずれも**、予約枠の変更/キャンセルが完了した時点で
  **「予約の変更（またはキャンセル）が完了しました」メール**を送る（金額のやり取りなし）。

### メール送信先（重要）
- **すべてのメール（申込受付・承認確定＝返金/追加請求/完了）は、顧客と管理者の双方へ送る。**
  - 顧客：予約者のメール。
  - 管理者：スペース別の通知先設定（#72）に従う（未設定はデフォルト管理者宛先）。
- 申込時：顧客「申請を受け付けました（内容・金額）」＋管理者「承認待ちが発生しました（要対応）」。
- 承認確定時：顧客「確定しました（返金/追加請求/完了）」＋管理者「確定を実行しました（控え）」。

### 補足
- **増額（時間追加）**：枠は申込時に確保。差額は承認時に**追加請求**で回収（現地/個別精算も可）。
- **チケット予約**：§3・§4 のルールに従い、承認確定時にチケット時間を返還/失効/付替（現金精算なし）。
- キャンセルの「3日前以降はオンライン不可（フォーム誘導）」の旧ゲートは**廃止**し、全期間オンラインで申込可能にする。
- ゲスト予約（会員登録なし）：3点照合の変更ページから同様（申込＝仮押さえ、確定＝管理者承認）。
- 管理者は原則お客様の要望に応える（承認前提）。金額調整のための承認であり、スケジュール自体の拒否は例外運用。

## 6. 実装フェーズ

- **Phase A**：チケット新ルール（§3・§4）の純粋ロジック＋テスト、チケットキャンセル境界（当日→当日・前日失効）変更。
- **Phase B**：現金キャンセルの「リクエスト→承認」統一（即時セルフ廃止）、変更承認での自動書き換え、管理画面の返金額編集、マイグレーション、メール、テスト。
- **Phase C**：お客様向け表示文言の全面更新（マイページ・完了画面・ガイド・メール・ゲスト変更ページ）＋制作ブリーフ反映。
