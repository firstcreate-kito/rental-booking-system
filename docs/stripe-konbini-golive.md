# コンビニ払いの本番化 & テスト↔本番の切り替え手順（#39）

システム側はコンビニ払いに**実装済み**です。必要なのは **Stripe側の設定**と、
**鍵（wrangler secret）の登録**だけ。コード変更は不要です。

---

## 0. 大前提：テストと本番は「鍵」で切り替わる（何度でも往復可）

Stripe には **テストモード**と**本番モード**があり、それぞれ別の鍵・別のWebhook・別のデータを持ちます。
どちらで動くかは、システムに登録した鍵で決まります。

| 用途 | シークレットキー | Webhook署名シークレット |
|---|---|---|
| テスト | `sk_test_...` | テスト用エンドポイントの `whsec_...` |
| 本番 | `sk_live_...` | 本番用エンドポイントの `whsec_...` |

**切り替え＝鍵を入れ替えて再デプロイするだけ**。戻すのも同じ手順で、**いつでも往復できます**。

```
npx wrangler secret put STRIPE_SECRET_KEY        # sk_test_... または sk_live_...
npx wrangler secret put STRIPE_WEBHOOK_SECRET     # そのモードの whsec_...
npm run deploy
```

> ⚠️ **必ずセットで合わせる**：`sk_test_` にはテスト用の `whsec_`、`sk_live_` には本番用の `whsec_`。
> 混在すると入金通知（Webhook）の署名検証に失敗し、予約が「最終確認中」のまま止まります。

### ⚠️ 現状の注意（本番サイトは1つだけ）
テスト専用の別環境（ステージング＝#84）はまだありません。本番サイトを一時的にテストにする場合：
- **テストモード中は実際のお客様がカード決済できません**（テスト鍵は本物のカードを拒否）。
  → テストは**営業時間外・短時間**で行い、終わったら本番鍵に戻す。
- **テストで作った予約はD1・Googleカレンダーに“本物”として残ります** → テスト後に削除。
- 安心して試すには **#84 ステージング環境**の構築がおすすめ（別URL・テスト鍵専用）。

---

## 1. テストモードでコンビニ払いを試す（推奨・実入金なし）

まずはテストモードで一連の流れを確認できます（本物のお金は動きません）。

1. Stripeダッシュボード右上を**「テスト環境」**に切替。
2. 左メニュー **「設定」→「支払い方法」** で **コンビニ決済（Konbini）** を**有効化**。
3. **「開発者」→「Webhook」→「エンドポイントを追加」**：
   - URL：`https://booking.space-albe.com/api/webhooks/stripe`
   - リッスンするイベント：
     - `checkout.session.completed`
     - `checkout.session.async_payment_succeeded` ←**コンビニ入金確定はこれ**
     - （任意）`checkout.session.async_payment_failed` ←支払い期限切れの検知用
   - 作成後に表示される **署名シークレット `whsec_...`** をコピー。
4. 鍵を登録（テスト用）：
   ```
   npx wrangler secret put STRIPE_SECRET_KEY        # sk_test_...
   npx wrangler secret put STRIPE_WEBHOOK_SECRET     # 手順3の whsec_...
   npx wrangler secret put STRIPE_KONBINI_ENABLED    # true
   npm run deploy
   ```
5. 予約フローでコンビニ払いが選べる条件（下記）を満たす予約を作成し、
   Stripeのテスト用コンビニ決済で「支払い済み」を確認 → 予約が本予約になることを確認。

### コンビニ払いが表示される条件（システム仕様）
- `STRIPE_KONBINI_ENABLED=true`（本番/テストとも）
- そのスペースの支払いモードが **「カード＋コンビニ＋銀行振込」(`card_konbini_bank`)**
- **会員ログイン中**（ゲストはカードのみ）
- **利用日まで5日以上**（直前予約はカードのみ）

---

## 2. 本番モードへ切り替え（公開時）

テストで問題なければ本番へ。

1. ダッシュボード右上を**「本番環境」**に切替。
2. **「支払い方法」で Konbini を有効化**（本番側でも申請/有効化が必要）。
3. **「開発者」→「Webhook」**で本番用エンドポイントを**同じURL・同じイベント**で追加し、
   本番用の **`whsec_...`** をコピー。
4. 鍵を本番に入れ替え：
   ```
   npx wrangler secret put STRIPE_SECRET_KEY        # sk_live_...
   npx wrangler secret put STRIPE_WEBHOOK_SECRET     # 本番の whsec_...
   npx wrangler secret put STRIPE_KONBINI_ENABLED    # true
   npm run deploy
   ```

### テストへ戻す場合
手順1の逆で、`sk_test_...` とテスト用 `whsec_...` を `wrangler secret put` し直して `npm run deploy`。
（`STRIPE_KONBINI_ENABLED` はそのままでOK。テスト/本番どちらでも有効化フラグとして働きます）

---

## 3. 運用上の重要な注意（コンビニ特有）

コンビニ払いは**入金までに数日**かかります。本システムは「**入金確定してから予約を確定**」する
決済先行フロー（#68）のため：

- コンビニ選択時、予約は **「pending（確認中）」で作成**され、**入金があるまで枠は確保されません**。
  → 入金前に**別のお客様がカードで同じ枠を確定**する可能性があります。
  その場合、コンビニ入金時に「満室で不成立」となり、**返金は手動対応**（コンビニ払いは自動返金不可のため、
  お客様に口座を伺って振込返金）になります。
- 上記リスクを踏まえ、システムは**利用日5日以上前のみ**コンビニ払いを許可しています。
- 返金時：管理画面の「返金」は、コンビニ払いは自動実行されず**手動対応の案内**になります（#87の仕様どおり）。

> 気になる場合の将来対応：「コンビニ選択中は枠を仮押さえ（tentative）する」設計変更も可能です（別途ご相談）。

---

## 4. 動作確認チェックリスト

- [ ] コンビニ払いが「対象スペース・会員・5日前以上」で選択肢に出る
- [ ] コンビニ選択→予約が pending で作成される（管理画面には未確定として出ない）
- [ ] テスト用コンビニ決済で入金 → `async_payment_succeeded` 受信 → 予約が本予約化・カレンダー反映・領収書発行・確認メール
- [ ] 未入金のまま期限切れ → 予約は pending のまま（枠は確保していないので実害なし）
- [ ] 本番切替後、実カードで少額の実決済テスト → 即確定を確認（確認後キャンセル/返金）

## メモ
- PayPal も同様にテスト/本番を切替可：`PAYPAL_MODE`（`sandbox`/`live`）＋ `PAYPAL_CLIENT_ID` / `PAYPAL_CLIENT_SECRET`。
- 鍵は `wrangler secret`（暗号化保存）で管理。コードやGitには含めません。
- Webhookが遅延・不達でも、決済完了ページの再確認でシステム側が入金照合して確定します（取りこぼし防止・実装済み）。
